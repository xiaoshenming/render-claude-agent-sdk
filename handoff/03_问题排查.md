# 问题排查

## 创建虚拟环境时 `ensurepip` 失败

先将整个包移动或重新解压到短路径，例如：

```text
D:\ManimQualityAgent_20260726
```

不要叠加多层中文长目录后再创建 `.venv`。必要时启用 Windows Long Paths，
但交接验证默认仍以短路径为准。

## `logic_engine_mvp` 无法导入

先确认使用 `agent\.venv\Scripts\python.exe`，并执行：

```powershell
.\handoff\scripts\setup_agent.ps1
```

冻结的 `logic_engine_mvp` 已位于
`agent/vendor/logic_engine_mvp_baseline`，不是外部仓库依赖。

## 缺少 `quality_repair`

执行：

```powershell
& .\agent\.venv\Scripts\python.exe `
  .\agent\scripts\materialize_quality_repair.py
```

脚本会从包内冻结归档生成 `agent/.vendor/quality_repair` 并校验 Hash。不要手工
复制旧目录，也不要修改冻结清单。

仓库级 `scripts/verify_vendor_sources.py` 还会审计不参与本线路的历史
`logic_self_audit_baseline`，该历史快照存在已记录的旧 Hash 不一致。部署当前
统一 Agent 应以 `setup_agent.ps1` 的 active-runtime 验收为准，不要修改历史
Hash 来制造全绿。

## Python 3.12/3.13 安装失败

Agent 平台锁定 Python `>=3.11,<3.12`。请安装 Python 3.11 后重新执行
`setup_agent.ps1`。Manim 渲染解释器可按目标项目环境单独选择。

## Manim 导入失败

`-ManimPython` 必须指向真正包含 Manim 的解释器，不是 Agent 的 `.venv`
就一定可以。运行：

```powershell
& "D:\runtime\python.exe" -c "import manim; print(manim.__version__)"
```

## `BaseConfigScene` 或项目模块导入失败

将其导入根目录传给 `-RuntimePythonPath`。该路径只进入受控渲染子进程，不会
扩展 Agent 文件权限。

## ffmpeg/ffprobe 找不到

安装 FFmpeg 并把 `bin` 加入 `PATH`，重开 PowerShell：

```powershell
ffmpeg -version
ffprobe -version
```

## Agent 能跑，但最终是 HOLD

这是正常的失败关闭，不是断链。查看：

```text
output/decision.json
logs/tool_calls.jsonl
agent_runtime/**/render.log
acceptance_runtime/**/layout_detector.json
```

常见原因：

- 修复后仍有阻塞 finding；
- R1/R2 未完成真实验证；
- 仍有阻塞重叠；
- 修改触碰题目或语义指纹；
- 工具调用或 turns 达到上限；
- 外层重新渲染失败。

## compile-only 为什么永远不能交付

`--compile-only` 只诊断 SDK 协议和工具链，缺少真实视频与布局证据，因此必须
HOLD。不能把 compile-only 的成功当成视频修复成功。

## 17 题复现结果与旧结果不一致

模型和兼容网关具有非确定性。先核对：

- `PACKAGE_INFO.json` 和输入 Hash；
- 模型名、网关协议、SDK 版本；
- turns、tool calls、并发和超时；
- Manim/字体/LaTeX 环境；
- 是否使用全新输出目录。

重复运行用于测稳定性，不应期待字节级一致。
