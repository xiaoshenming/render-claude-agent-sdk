# 获取、核验与恢复说明

## 从本分支获取

```bash
git fetch origin
git switch codex/server3-logic-overlap-agent-backup-20260804
python handoff/server3-logic-overlap-20260804/verify_snapshot.py
```

如果该分支尚未推送，应由交接人提供本地仓库路径或 Git bundle；不要假设远端分支已经存在。

## 查看归档但不覆盖文件

```bash
tar -tzf vendor/source_archives/server3_render_logic_overlap_runtime_20260804.tar.gz | less
```

解压时使用一个新目录：

```bash
mkdir -p /tmp/server3-render-agent-snapshot-20260804
tar -xzf vendor/source_archives/server3_render_logic_overlap_runtime_20260804.tar.gz \
  -C /tmp/server3-render-agent-snapshot-20260804
```

不要解压到当前仓库根目录或正在运行的 Render 目录。

## 以后重新从 server3 获取

凭据必须来自受控配置，不要把密码或 Key 写进命令历史、文档或提交。以下示例假定操作者已有三个环境变量：`SERVER3_HOST_VALUE`、`SERVER3_USER_VALUE`、`SERVER3_PASSWORD_VALUE`。

```bash
sshpass -p "$SERVER3_PASSWORD_VALUE" ssh \
  -o StrictHostKeyChecking=no \
  "$SERVER3_USER_VALUE@$SERVER3_HOST_VALUE" '
set -e
systemctl show mathpi-render \
  -p ActiveState -p SubState -p MainPID -p ExecStart -p WorkingDirectory
cd /opt/mathpi/apps/render
tar --exclude="*/__pycache__" \
    --exclude="*.pyc" \
    --exclude="*.bak*" \
    --exclude=".env" \
    --exclude=".env.*" \
    -czf - app requirements.txt
' > server3_render_logic_overlap_runtime_NEW.tar.gz
```

获取后必须执行：

```bash
sha256sum server3_render_logic_overlap_runtime_NEW.tar.gz
tar -tzf server3_render_logic_overlap_runtime_NEW.tar.gz | sort
```

还必须单独记录：采集时间、hostname、systemd WorkingDirectory/ExecStart/MainPID、服务启动时间、非敏感模型配置、依赖版本和关键入口 SHA。不要把 `.env` 整体打印到日志。

## 与新版本比较

```bash
mkdir -p /tmp/server3-agent-old /tmp/server3-agent-new
tar -xzf vendor/source_archives/server3_render_logic_overlap_runtime_20260804.tar.gz \
  -C /tmp/server3-agent-old
tar -xzf server3_render_logic_overlap_runtime_NEW.tar.gz \
  -C /tmp/server3-agent-new
diff -ruN /tmp/server3-agent-old/app/quality_platform /tmp/server3-agent-new/app/quality_platform
diff -ruN /tmp/server3-agent-old/app/workers/validation/math_logic /tmp/server3-agent-new/app/workers/validation/math_logic
diff -ruN /tmp/server3-agent-old/app/workers/validation/layout /tmp/server3-agent-new/app/workers/validation/layout
```

差异报告要区分：逻辑提示词、模型路由、SDK 调用、工具权限、预算、修复轮数、BBox/重叠分类、fail-open 行为、接入点和纯格式差异。

## 恢复原则

这份包只提供可追溯基线，不授权直接部署。需要恢复到 server3 时：

1. 从归档解压到隔离目录。
2. 与当前 server3 逐文件比较，形成明确恢复清单。
3. 备份即将覆盖的远端文件。
4. 排除 `.env`、venv、证书、媒体、缓存和任务数据。
5. 只同步经过审核的文件。
6. 编译检查后再重启服务。
7. 验证 `/health`、8 个容器状态和 systemd 实际进程路径。
8. 发布最小 canary，核验逻辑事件、重叠事件、Token、最终视频与可回滚性。

任何恢复或部署都应遵守目标环境自己的部署技能和审批边界。
