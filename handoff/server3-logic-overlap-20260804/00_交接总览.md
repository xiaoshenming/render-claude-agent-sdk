## 冻结范围

归档包含 server3 当时的完整 `app/` 与 `requirements.txt`，而不是只摘抄几个 Agent 文件。这样可以保留逻辑审查、逻辑修复、BBox/重叠检测、布局修复、质量编排、归档接入和所有真实依赖之间的精确关系。

核心区域：

- `app/quality_platform/`：归档前质量平台、V3 runner、SDK review、桥接与三态结果。
- `app/quality_repair/`：质量修复控制器、Agent、证据、布局 MVP、Patch Guard 与渲染适配。
- `app/workers/validation/math_logic/`：逻辑 Reviewer、提示词、证据、确定性校验与修复合同。
- `app/workers/validation/layout/`：BBox probe、重叠分类、布局 Agent、修复计划和运行态证据。
- `app/workers/validation/math_logic_*.py`、`quality_repair_*.py`：顶层兼容与策略文件。
- `app/workers/minimal_archive.py`、`app/quality_platform/pre_archive.py`：普通生成进入质量 Agent 的生产接入点。

`SOURCE_MANIFEST.sha256` 记录 226 个核心文件的 SHA-256。归档同时保留完整 Render `app/`，用于解决只复制核心目录后出现隐式依赖缺失的问题。

## 实际 Agent 路线

普通生成完成基础渲染后，从 `minimal_archive` 进入 `quality_platform.pre_archive`，再由 `quality_platform.v3_runner` 启动质量流程：

1. Logic Reviewer 读取题意、源码和渲染证据。
2. 需要时执行 Logic Repair，并重新检查候选版本。
3. Layout/Overlap 运行 BBox 与重叠证据检查。
4. 需要时执行布局修复和后续复查。
5. 质量平台记录 `deliver`、`deliver_with_warning` 或 `fail_open`，再回到归档链路。

V3 runner 把同一个 `QUALITY_MODEL` 交给逻辑和布局/重叠 SDK 路线；本冻结版本对应 `deepseek-v4-flash`。
