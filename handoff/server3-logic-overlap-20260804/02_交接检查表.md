# 接收与交接检查表

## 交付方

- [ ] 告知仓库绝对路径、分支名和提交 SHA。
- [ ] 说明分支是否已经推送；没有推送时提供本地访问方式或 Git bundle。
- [ ] 运行 `verify_snapshot.py`，归档和 947 个核心文件全部通过。
- [ ] 明确采集时间、server3 hostname、服务名、WorkingDirectory、ExecStart 和启动时间。
- [ ] 明确逻辑 Agent 与重叠 Agent 使用的模型和协议入口。
- [ ] 明确哪些配置来自 `.env`，哪些来自源码默认值。
- [ ] 确认归档不含 `.env`、Key、日志、任务数据、数据库和视频。
- [ ] 说明这是只读冻结包，没有对 server3 做部署或重启。
- [ ] 提供已知运行效果与数据缺口，不把数据库成功等同于最终媒体成功。

## 接收方

- [ ] 从指定分支获取，不从主分支或相似实验分支猜版本。
- [ ] 先验证 SHA，再解压到隔离目录。
- [ ] 阅读目标仓库 `AGENTS.md`、架构与 Harness 文档。
- [ ] 不把冻结归档当成可直接 import 的活动源码。
- [ ] 不把服务器凭据或模型 Key 写进代码、Prompt、日志或提交。
- [ ] 先画出接入点和依赖关系，再决定移植、对比或恢复。
- [ ] 若要移植，保持 Logic Reviewer、Logic Repair、Overlap/Layout 和外部证据检查的职责边界。
- [ ] 若要部署，先备份、做差异清单、跑测试和 canary，再验证真实任务。
- [ ] 将模型、Prompt、Schema、工具权限、预算与事件版本分别记录。

## 完成交接的证据

交接完成至少应提供：

1. `git branch --show-current` 与 `git rev-parse HEAD`。
2. `verify_snapshot.py` 的成功输出。
3. 归档 SHA-256。
4. 解压后的关键入口 SHA 与 `SOURCE_MANIFEST.sha256` 一致。
5. 一份接收结论：仅归档、已完成对比、已移植但未部署，或已 canary 验证。
6. 若发生部署，补充 systemd、进程路径、健康、容器、真实任务、质量事件和最终媒体证据。

## 不算完成

- 只看到分支名。
- 只解压成功。
- 只通过 Python 编译或单元测试。
- 只看到 HTTP 200。
- 只看到数据库任务 SUCCESS。
- Agent 自己声称已修复但没有独立重渲染和证据复查。
