# 四题后半段异常：人工诊断与修复报告

## 结论

这四题的主要异常并不是此前归纳的“坐标空间漂移”，而是一类新的场景对象生命周期错误：

```text
transient_mobject_lifecycle_leak
临时 Mobject 场景驻留 / 生命周期泄漏
```

共同机制如下：

1. 代码在高亮、重强调等动画中使用了后建对象，甚至直接内联创建 `Line(...)`。
2. 这些对象参与 `Indicate`、`Create` 等动画后，会被 Manim 自动加入当前 Scene。
3. 它们没有加入当前阶段的所有者组，例如 `geometry_all1`。
4. 切换到下一问时，代码只执行 `FadeOut(geometry_all1)`。
5. 因为辅助对象不属于 `geometry_all1`，它们没有退出 Scene，继续覆盖在后续画面上。

因此用户看到的现象像“图形漂移”，实质却是上一阶段的对象没有被销毁。

## 我是如何发现的

### 1. 先看视频后半段，而不是只看最终帧

四份原视频都从总时长约 48% 处开始逐秒抽帧，重点观察：

- 第一张图退出的瞬间；
- 第二张图进入前后的 1～3 秒；
- 高亮、填充、辅助线是否在切场后仍存在；
- 后续图形是否真的移动，还是旧对象留在原处。

观察到：

| 编号 | 后半段可见症状 | 判断 |
|---|---|---|
| 035 腰上的高求底角 | 第一问三角形的边和填充继续留在第二问画面 | 旧强调对象未退出 |
| 047 练习2 | 切场时残留橙色 L 形辅助线 | 内联高亮线成为 Scene 驻留对象 |
| 054 练习4 | 图一的 BP/CD 重强调辅助线存在跨阶段残留风险 | 临时重强调线没有阶段 owner |
| 117 第56题 | 第一问退出后仍留下水平辅助边 | 后建边不属于退出组 |

### 2. 反查 `Solution.construct`

我没有先套用“漂移”结论，而是沿着可见残影反查对象创建位置、第一次动画使用位置和切场位置。

关键代码模式是：

```python
self.highlight_edge(Line(...))
self.reemphasize_equal_segments(Line(...), Line(...))
```

以及：

```python
geometry_all1 = VGroup(...)
...
edge_AE = Line(...)
...
self.play(FadeOut(geometry_all1))
```

这说明辅助对象是在总组形成后才创建的，且没有加入总组。动画让它进入 Scene，而退出动画只处理总组，正好解释了视频后半段的残影。

### 3. 做最小修复并重新渲染

修复只改四份隔离副本中的 `class Solution(BaseConfigScene)` 核心逻辑：

- 把临时对象命名；
- 使用适配完成后的最终坐标创建；
- 将其加入所属阶段的 `geometry_all1` / `geometry_all2`；
- 后续动画复用同一个对象；
- 不改全局框架、渲染器、依赖类和原始样本。

四份代码均通过 AST/编译，并以四路并发重新渲染。修复后逐秒检查后半段，旧阶段对象均可随 owner group 正常退出。

## 四题具体修复

### 035 腰上的高求底角

问题对象：

```python
edge_AB1
edge_AC1
region_ABC1
edge_AB2
edge_AC2
region_ABC2
```

这些对象在布局适配后创建，但不属于两阶段的 `geometry_all`。

修复：

```python
geometry_all1.add(edge_AB1, edge_AC1, region_ABC1)
geometry_all2.add(edge_AB2, edge_AC2, region_ABC2)
```

结果：第一问的边和填充会随第一阶段整体退出，不再叠到第二问。

### 047 全等三角形综合（一）· 练习2

问题对象是动画调用中临时创建的多条线：

```python
Line(pt_A1, pt_P1)
Line(pt_B1, pt_Q1)
Line(pt_B1, pt_P1)
Line(pt_B2, pt_P2)
Line(pt_B2, pt_Q2)
```

修复后先创建具名对象：

```python
helper_AP1
helper_BQ1
helper_BP1
helper_BP2
helper_BQ2
```

再将它们加入对应阶段的 owner group，并让所有高亮调用复用这些对象。

结果：切场处橙色 L 形残影消失，第二问从干净场景开始。

### 054 全等三角形综合（一）· 练习4

问题代码在重强调时内联创建 BP、CD：

```python
self.reemphasize_equal_segments(
    Line(dot_B1.get_center(), dot_P1.get_center()),
    Line(dot_C1.get_center(), dot_D1.get_center()),
)
```

修复：

```python
helper_BP1 = Line(...)
helper_CD1 = Line(...)
geometry_all1.add(helper_BP1, helper_CD1)
```

重强调调用复用 `helper_BP1`、`helper_CD1`。

结果：两条强调线具备明确的第一阶段生命周期，不会成为切场后的孤儿对象。

### 117 全等三角形综合（一）· 第56题

问题对象：

```python
edge_AE
edge_AD
edge2_AE
edge2_AD
```

这些边在两个 `geometry_all` 创建后才生成。

修复：

```python
geometry_all1.add(edge_AE, edge_AD)
geometry_all2.add(edge2_AE, edge2_AD)
```

结果：第一阶段退出后不再留下水平边，第二阶段自身的强调边也由第二阶段统一管理。

## 为什么原 Reviewer 没有审出来

Reviewer 拿到了完整 `Solution`，问题并不在“代码给得不完整”，而在检查合同缺失。

原提示词重点覆盖：

- 点、线、标签是否使用同一套坐标；
- `fit_geometry_group` 后是否重新取坐标；
- 静态对象是否应该使用 updater；
- 图形切换是否调用 FadeOut；
- 数学结论和画面是否一致。

但它没有要求 Reviewer 建立 Scene 驻留对象清单，也没有要求验证：

```text
每一个被动画使用、因而可能进入 Scene 的 Mobject，
是否属于当前阶段 owner，
以及在阶段结束时由谁移除。
```

所以 Reviewer 看到 `FadeOut(geometry_all1)` 会倾向认为“第一阶段已经清理”，却没有继续验证高亮函数内部或内联 `Line(...)` 是否产生了总组之外的 Scene 对象。

这也是 Coder 修不好的原因：Reviewer 没给出生命周期问题，Coder只能继续围绕坐标漂移、标签绑定或局部替换修补，无法命中真实因果链。

## 应反馈到 Reviewer 的最小提示词

建议只增加下面这一小段，不必加入大段 Manim 教程：

```text
【场景生命周期检查】
对每次图形阶段切换，检查所有曾传入 Create/Write/FadeIn/Indicate/
Transform 或自定义高亮函数的 Mobject。动画可能把对象加入 Scene。
确认每个非全局对象都属于该阶段的 owner VGroup，或在阶段结束时被显式移除。
特别检查：
1. 动画参数中内联创建的 Line/Polygon/MathTex；
2. owner VGroup 建立后才创建的强调边、填充和辅助线；
3. FadeOut(owner) 后仍可能驻留的对象。
若存在，报告 transient_mobject_lifecycle_leak，并指出对象、进入 Scene
的位置、缺失的 owner/退出动作和可见残影发生阶段。
```

## 应反馈到 Coder 的修复合同

```text
遇到 transient_mobject_lifecycle_leak：
1. 不要只在末尾补 FadeOut；
2. 将临时对象改为具名对象；
3. 在最终布局/fit 后创建；
4. 加入所属阶段 owner VGroup；
5. 后续动画复用同一对象；
6. 确保 FadeOut(owner) 能统一清理。
```

统一归属优于在多个切场点散落 `FadeOut(helper)`，因为后者容易再次漏掉。

## 可加入的证据型静态检查

可增加一个 fail-open、只提供证据的 AST 检查器，标记以下模式：

- `highlight_*` / `reemphasize_*` / `Indicate` 参数中直接出现 `Line(...)`、`Polygon(...)`；
- `geometry_all = VGroup(...)` 之后新建的 Mobject 被动画使用，但没有 `.add(...)` 到 owner；
- 某阶段使用了对象，但阶段结束的 `FadeOut`/`remove` 路径覆盖不到它。

检查器只需要给 Reviewer 提示，不应阻断渲染。
