# Workbench E2E 45-Run Plan

## Objective

Validate the existing Manim quality workbench on generated, renderable lessons rather than curated repair-only samples. Run three rounds of 15 jobs from a frozen pool of 20 moderately hard math topics, preserve complete evidence, and make only generic harness or prompt improvements between rounds.

## Scope

- Generate Manim code through the existing Anthropic-compatible `/v1/messages` gateway.
- Render every generated candidate before quality processing.
- Run the existing mandatory logic reviewer and its conditional repair path.
- Run real layout probing and invoke the existing overlap repair path only when blocking overlap evidence exists.
- Re-render changed candidates and record the final delivery decision.
- Keep the expected/actual relation probe disabled for this experiment.
- Keep all experiment integration under `evals/workbench_e2e`; do not change production Agent behavior.

## Frozen Workload

- Freeze 20 topic records before the first measured round.
- Each record contains the problem, an independently checkable solution outline, expected answer or theorem, domain, difficulty, and prompt profile.
- Use 45 deterministic execution slots: 15 per round for three rounds.
- Rotate the 20 records so all are covered and repeated records provide stability evidence.
- Favor geometry proof, coordinate geometry, functions, algebraic reasoning, probability, and statistics. Exclude trivial one-step exercises.

## Allowed Iteration

Between rounds, changes may improve only:

- environment isolation and deterministic process invocation;
- generic prompt contracts and output parsing;
- stage timeouts, bounded retries, and concurrency;
- evidence extraction, logging, and failure classification;
- domain-level prompt routing that is fixed before the next round.

Changes must not branch on task IDs, object names, exact equations, or individual sample wording. Every change requires a short hypothesis and before/after metric.

## Evidence Per Job

- frozen input and prompt profile identifier;
- generated source and generation response metadata;
- input, output, and total tokens for every LLM or Agent call;
- wall time, attempts, and terminal status for every stage;
- baseline and final render logs, videos, and source hashes;
- logic review report, repair patch, directed verification, and re-render result;
- layout snapshots, blocking issue summary, repair patch, and recheck result;
- final decision with explicit reason and any fail-open warning.

Secrets are supplied only through process environment variables and must be redacted from logs and reports.

## Acceptance

The run is complete only when:

1. All 45 slots have terminal records, including failed jobs.
2. Every claimed success has a successful final render and persisted quality evidence.
3. Token and wall-time totals reconcile from call level to job, round, and experiment summaries.
4. Round changes are generic and documented; no per-case code or prompt branches exist.
5. The report separates generation failure, render failure, reviewer failure, repair failure, overlap failure, and delivery hold.
6. A human-readable HTML index links before/after videos, source, patches, and logs.

## Stop Rules

- Do not hide or retry away terminal failures.
- Stop a single job after its bounded stage budget; continue the batch.
- Do not continue an optimization after a round if quality is flat or worse without a clear, evidence-backed cause.
- Preserve each round's code revision, configuration snapshot, and artifacts.

## Implementation Order

1. Add tested workload, prompt-source, generation, process, and evidence primitives.
2. Add tested stage adapters around the existing renderer, logic flow, and layout probe/repair package.
3. Add a resumable CLI and deterministic manifest.
4. Run two smoke jobs and fix only harness-level defects.
5. Freeze the measured configuration and run round 1.
6. Audit round 1, record one generic optimization hypothesis, then run round 2.
7. Run round 3 only with a justified frozen configuration.
8. Verify artifacts and publish Markdown, JSON, CSV, and HTML reports.
