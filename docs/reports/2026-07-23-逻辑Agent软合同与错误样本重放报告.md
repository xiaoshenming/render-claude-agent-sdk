## 二、实现内容

### 1. 历史最佳候选

新增 `CandidateHistory`：

- 每轮保存候选源码；
- 优先保留解决 Issue 更多的候选；
- 后续候选变差时返回历史最佳；
- Verifier、SDK、Token 或格式异常不会清空历史候选。

### 2. 临时错误自动重试

如果 Coder 在任何 Edit 之前遇到：

- `server_error`；
- 临时 SDK 错误；
- 无结构化输出；

则使用剩余修复机会重新调用。

如果已经发生 Edit，则不重新解释为“无结果”，而是保存修改后的候选。

### 3. Read 与 turn 改为软预算

- Coder 最大 turn：`7 → 12`；
- Verifier 最大 turn：`4 → 8`；
- Logic Agent 工具总调用预算：`8 → 64`；
- 同一源码允许有界重复 Read；
- Read 行为记录 Token 和耗时，不再因为第 4 次读取直接否定候选。

### 4. Verifier逐项验收

每个 Issue 独立输出：

```text
resolved
unresolved
unknown
```

源码引用仍可保留，但只作为展示证据：

- 引用行号不准确，不否定代码；
- 引用没有严格命中 diff hunk，不否定代码；
- 不再因为引用格式触发整条结构化纠错；
- 最终采用由逐项判断和可执行候选共同决定。

### 5. Verifier直接接收完整候选

完整修改后源码已经放进 Verifier 输入，不再要求 Verifier 重新拼接临时路径读取 `candidate.py`。

这解决了实际出现的错误：

```text
path cannot be resolved:
.../workspace/opt/mathpi/candidate.py
```

- 后续应优化 Coder 的读取和编辑节奏，而不是重新缩紧上限或丢弃候选。
